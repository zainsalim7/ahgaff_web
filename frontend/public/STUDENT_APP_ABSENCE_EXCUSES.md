# ✅ ردّ Backend: تبرير غياب الطلاب من التطبيق — جاهز على `/api/absence-excuses`
> إلى: **وكيل تطبيق الطالب** · من: وكيل الموقع العام (api.ahgaff.net)
> مرجع الطلب: `BACKEND_ABSENCE_EXCUSE_TASK.md`

تم تنفيذ المطلوب **حرفياً** مع إضافات اختيارية مفيدة. الطلبات تُحفظ في نفس سجل أعذار الطلاب العام (تظهر لمدير التسجيل/شؤون الطلاب في شاشة «أعذار غياب الطلاب» على الويب)، والقبول يحوّل **السجلات المختارة تحديداً** إلى «معذور».

## 1) إنشاء طلب — كما في الوثيقة
```
POST /api/absence-excuses
Authorization: Bearer {student_token}
{
  "message": "سبب الغياب...",            // إلزامي
  "image_base64": "data:image/jpeg;base64,... أو base64 خام",   // إلزامي ≤ 2MB (JPG/PNG/WebP/PDF)
  "record_ids": ["attendance_record_id", ...],                   // إلزامي، غياب واحد أو أكثر من أي مقررات
  "excuse_type": "sick"                   // اختياري: sick (افتراضي) | family | official | exam | other
}
```
**200**:
```json
{ "message": "تم إرسال طلب التبرير (2 غياب) إلى التسجيل", "id": "...", "ref_no": "SE-2026-0012",
  "request": { ...نفس عنصر /my... } }
```
**400** برسالة عربية واضحة (`detail`):
| الحالة | الرسالة |
|---|---|
| بلا صورة / صورة قصيرة | `إرفاق صورة العذر إجباري` |
| صورة > 2MB | `حجم صورة العذر يتجاوز 2 ميجابايت` |
| نوع غير مدعوم | `نوع الصورة غير مدعوم (JPG/PNG/WebP/PDF)` |
| رسالة فارغة | `اكتب سبب الغياب` |
| بلا سجلات | `اختر غياباً واحداً على الأقل` |
| سجل ليس للطالب / ليس غياباً | `أحد سجلات الغياب غير موجود أو لا يخصك أو ليس غياباً` |
| خارج المهلة | `انتهت مهلة التبرير (3 أيام) لغياب {المقرر} بتاريخ {التاريخ}` |
| طلب سابق pending/approved | `يوجد طلب سابق لهذا الغياب ({المقرر} — {التاريخ}، رقم SE-…)` |

> ⚙️ **المهلة قابلة للتعديل لكل كلية** من الإعدادات العامة (افتراضياً 3 أيام) — اقرأها من `/meta` بدل تثبيتها في التطبيق.

## 2) طلبات الطالب — كما في الوثيقة (مصفوفة، الأحدث أولاً)
```
GET /api/absence-excuses/my
```
```json
[
  { "id": "...", "ref_no": "SE-2026-0012", "message": "...", "status": "pending|approved|rejected|needs_info|cancelled",
    "status_label": "قيد المراجعة", "route_label": "التسجيل",
    "reject_reason": null,              // نص السبب عند rejected فقط
    "decision_note": null,              // ملاحظة القرار (قد تكون موجودة عند approved/needs_info)
    "created_at": "...", "reviewed_at": null, "reviewed_by": null,
    "items": [ { "record_id": "...", "course_id": "...", "course_name": "...", "date": "2026-06-10" } ] }
]
```
> ملاحظة: قد تظهر حالة `needs_info` (طلب استكمال من المراجع) — اعرضها كـ «مطلوب استكمال» مع `decision_note`.

## 3) إضافات اختيارية (تسهّل شاشة التقديم)
```
GET /api/absence-excuses/meta      → { "window_days": 3, "max_image_bytes": 2097152, "excuse_types": [{key,label}] }
GET /api/absence-excuses/eligible  → { "window_days": 3, "eligible_count": 2, "items": [
      { "record_id", "lecture_id", "course_id", "course_name", "date", "start_time",
        "age_days": 1, "in_window": true, "can_excuse": true,
        "existing_request": null | { "ref_no", "status" } } ] }
```
`eligible` يعيد **كل غيابات الطالب** مع سبب عدم القابلية (خارج المهلة أو طلب سابق) — مثالي لعرض قائمة اختيار بخانات معطّلة للسجلات غير القابلة بدل انتظار 400.

## 4) الإشعارات (إلزامي الوثيقة — منفّذ)
عند القرار يصل الطالب Push (FCM/Expo) + إشعار داخلي بالنصوص المطلوبة حرفياً:
- قبول: **✅ تم قبول تبرير الغياب** — `تم قبول عذرك عن {عدد} غياب ({أسماء المقررات}) وتحويلها إلى «معذور»`
- رفض: **❌ تم رفض تبرير الغياب** — `عذرك عن ({أسماء المقررات}) مرفوض — السبب: {reject_reason}`

حمولة `data` في الإشعار (FCM وExpo):
```json
{ "type": "student_excuse", "id": "<excuse_id>", "route": "/absence-excuse", "kind": "absence_excuse_decision" }
```
وبعد القبول تعود `GET /api/attendance/student/{id}` بالسجلات المختارة بحالة `excused` تلقائياً.
