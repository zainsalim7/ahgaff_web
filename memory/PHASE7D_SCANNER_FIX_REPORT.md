### مثال موثَّق (دليل كود مباشر على نجاح الإصلاح)
```python
# routes/letters.py
P_ISSUE, P_SETTINGS = "issue_letters", "manage_letter_settings"
def _can(user): return has_permission(user, P_ISSUE) or has_any_permission(user, HR_PERMS)
def _guard(user):
    if not _can(user): raise HTTPException(403, "...")
@router.post("/letters")
async def issue_letter(..., current_user=Depends(get_current_user)):
    _guard(current_user)   # ← بلا أي وسيط صلاحية! الماسح v1 لا يرى شيئًا هنا إطلاقًا
```
الماسح v2 الآن: يرى `_guard(current_user)` ← يتعرّف أنها دالة محلية ← يفتح جسمها (يجد `raise` فعليًا ← `confirmed_raises`) ← يتتبّع أنها تستدعي `_can(user)` ← يفتح جسم `_can` ← يجد `has_permission(user, P_ISSUE)` ← يحلّ `P_ISSUE` عبر جدول الرموز إلى `"issue_letters"` ← **اكتشاف ناجح وموثَّق بالكامل عبر AST حقيقي، صفر تخمين**.

### ⚠️ خطأ اكتُشف وصُحِّح أثناء البناء (شفافية كاملة)
المحاولة الأولى لاكتشاف "صلاحية حصرية للأدمن" (`admin_only_detected`) قارنت نص AST المُفرَّغ (`ast.dump`) بنص المصدر الحرفي — وهذه مقارنة لن تتطابق أبدًا تقنيًا (الـAST لا يحتوي نص المصدر الحرفي). اكتُشف هذا فورًا عبر اختبار `test_excess_and_missing_coverage_fields_present` الذي فشل (0 أدوار بها `excess_flags`)، وصُحِّح عبر دالة `_detect_admin_only` تطابق بنية AST الدقيقة (`Compare` + `Subscript` + `NotEq` + `Constant`) بدل مقارنة نصية خاطئة. بعد التصحيح: **25 Endpoint** مكتشَفة كحصرية للأدمن، و**3 أدوار** ظهر لها `excess_flags` حقيقية (صلاحيات أدمن-فقط موجودة ضمن مرشَّحاتها الحالية — تستحق مراجعتك لاحقًا، لم تُغيَّر).

## 4) تصحيح الانحراف المكتشَف في 7-ج (118 ← طُبِّق فعليًا الآن)

نفَّذتُ بالضبط ما وافقتَ عليه:

3. **العدد النهائي الفعلي للصلاحيات الحساسة بعد التعديل: 122** (وليس 118 كما كان متوقَّعًا، لأن معايير العدّ لم تتغيّر لكن **عدد الـEndpoints الكلي نما حقيقيًا** من 976 إلى 1026 منذ المرحلة 2 — تحقَّق رياضيًا: 120 طبيعيًا من النمو + 2 من التصحيح = 122). هذا متوافق تمامًا مع تحذيرك "لا تفترض أن العدد سيبقى 976".
4. **ظهور التصنيف الصحيح في واجهة المراجعة**: تحقَّقت مباشرة أن `advanced_sensitive_permission_reviews` تُظهر `sensitivity: "high"` للصلاحيتين، وأن إجمالي مستندات المراجعة الآن **122** (متزامن تمامًا مع السجل، بعد أن كانا متباعدين 116 مقابل 118 في 7-ج).

6. **القيم السابقة والجديدة موثَّقة أعلاه بدقة** (116 → 120 طبيعيًا → 122 بعد التصحيح).

### السبب الجذري الحقيقي لفشل التطبيق سابقًا (دليل موثَّق بالطابع الزمني)
