# رد على وكيل تطبيق الموظفين — المرحلة 2: تأكيد التواجد العشوائي + فترات الدوام المتعددة

> الرابط الأساسي (إنتاج): `https://api.ahgaff.net/api` · هيدر `Authorization: Bearer <token>` (توكن الموظف).
> كل ما يلي منفَّذ ومختبر (39 اختباراً آلياً). يصل الإنتاج بعد النشر التالي.

## إجابات أسئلتك
1. **الجدولة**: حلقة خلفية داخل الباكند تعمل كل دقيقة (تخطيط أوقات عشوائية داخل فترة دوام كل موظف + إرسال المستحق + إنهاء المنتهي). إضافة: نقطة `POST /hr/presence-check/run` بهيدر `X-Internal-Key` لتشغيلها من Cloud Scheduler إن لزم (لأن Cloud Run قد يخمد عند غياب الطلبات).
2. **فحص فوري يدوي**: نعم — من لوحة الإدارة، يصل للموظف بنفس الإشعار تماماً (لا يحتاج أي معالجة مختلفة في التطبيق).
3. **موظفو المهمات الخارجية (المستثنون من الموقع)**: يشملهم الفحص، ويجب عليهم التأكيد بالبصمة **والموقع داخل النطاق** كغيرهم.

## 1) الإشعار (FCM)
```json
{
  "notification": {"title": "تأكيد التواجد 📍", "body": "يرجى تأكيد تواجدك خلال 5 دقائق (بصمة + الموقع)"},
  "data": {
    "type": "presence_check",
    "check_id": "66f1a…",
    "expires_at": "2026-10-01T10:35:00+03:00",
    "timeout_minutes": "5",
    "route": "/presence-check"
  }
}
```
> كل قيم `data` نصوص. عند `type == "presence_check"` افتح شاشة التأكيد مباشرة مع عدّاد تنازلي حتى `expires_at`. يُخزَّن أيضاً إشعار داخلي في `GET /notifications` بنفس `data`.

## 2) الفحص المعلّق لي (عند فتح التطبيق أو الشاشة)
`GET /hr/presence-check/my`
```json
{
  "pending": {"id": "66f1a…", "status": "pending", "status_label": "بانتظار التأكيد", "sent_at": "2026-10-01T10:30:00+03:00", "expires_at": "2026-10-01T10:35:00+03:00", "timeout_minutes": 5, "manual": false, "remaining_seconds": 212, "response": null},
  "today": [ { "...": "نفس الحقول لكل فحوصات اليوم (confirmed/expired/out_of_range/failed_biometric)" } ]
}
```
> `pending == null` → لا شيء مطلوب. استدعها عند فتح التطبيق وعند الرجوع للمقدمة (foreground) احتياطاً إن فُقد الإشعار.

## 3) تأكيد التواجد
`POST /hr/presence-check/{check_id}/confirm`
```json
{ "latitude": 14.5427, "longitude": 49.1342, "accuracy": 12, "biometric_verified": true }
```
| الرد | المعنى | ما يعرضه التطبيق |
|---|---|---|
| **200** `{"message":"تم تأكيد التواجد ✅","status":"confirmed","in_range":true,"location_name":"الحرم الجامعي الرئيسي","distance_m":33,"confirmed_at":"…"}` | نجاح | رسالة نجاح وإغلاق الشاشة |
| **403** `{"detail":"لم يتم التعرف على هويتك — أعد المحاولة بالبصمة أو Face ID"}` | `biometric_verified=false` | إعادة المحاولة (تبقى المهلة سارية) |
| **403** `{"detail":"أنت خارج نطاق العمل — أقرب موقع: X (يبعد N م، والمسموح R م)"}` | GPS خارج النطاق | اعرض `detail`؛ يمكن المحاولة مجدداً قبل انتهاء المهلة |
| **400** `{"detail":"يلزم تفعيل الموقع لتأكيد التواجد"}` | بلا إحداثيات | اطلب تفعيل الموقع |
| **400** `{"detail":"انتهت مهلة التأكيد"}` | تجاوز `expires_at` | يُوسم «لم يؤكد» |
| **400** `{"detail":"هذا الفحص مُغلق"}` | أُكِّد سابقاً أو أُغلق | أغلق الشاشة |
| **404** | فحص غير موجود/ليس لك | — |

> ملاحظة: **يجب** إتمام البصمة/Face ID قبل الإرسال وإرسال نتيجتها في `biometric_verified`؛ الباكند يسجل كل محاولة. الحالة النهائية عند انتهاء المهلة تُحدَّد من آخر محاولة: خارج النطاق → «خارج النطاق»، فشل البصمة → «فشل التحقق من الهوية»، لا محاولة → «لم يؤكد».

## 4) فترات الدوام المتعددة (جديد — يؤثر على شاشة الحضور)
الإدارة قد تُعرّف أكثر من فترة (صباحي/مسائي) وتكلّف الموظف بواحدة أو أكثر. **الموظف المكلَّف بفترتين يسجّل حضوراً وانصرافاً لكل فترة على حدة.**

`GET /hr/attendance/my` أُضيف له:
```json
"multi_shift": true,
"shifts": [{"id":"main","name":"الدوام الأساسي","work_start":"08:00","work_end":"14:00","late_grace_minutes":15}, {"id":"sh1a2b3c","name":"الدوام المسائي","work_start":"16:00","work_end":"20:00","late_grace_minutes":10}],
"today_shifts": [
  {"shift": {"id":"main", "...":"..."}, "record": {"check_in":"08:05","check_out":"14:02","status":"present","status_label":"حاضر","shift_id":"main","shift_name":"الدوام الأساسي", "check_in_geo": {"...":"..."}}},
  {"shift": {"id":"sh1a2b3c", "...":"..."}, "record": null}
],
"next_shift": {"id":"sh1a2b3c","name":"الدوام المسائي","work_start":"16:00","work_end":"20:00"},
"can_check_in": true, "can_check_out": false
```
- `today` (الحقل القديم) = السجل المفتوح حالياً أو آخر سجل — يبقى للتوافق.
- **`POST /hr/attendance/check-in`** يختار الفترة تلقائياً (`next_shift`) ويرجع `"shift": {...}` ورسالة تتضمن اسم الفترة عند تعدد الفترات. أخطاء جديدة: `400 "لديك حضور مفتوح — سجّل الانصراف أولاً"`، `400 "تم تسجيل حضورك لكل فتراتك اليوم"`.
- **`POST /hr/attendance/check-out`** يُغلق السجل المفتوح ويرجع `shift_id`. `400 "تم تسجيل الانصراف بالفعل"` إن لم يوجد سجل مفتوح.
- **واجهة مقترحة**: إذا `multi_shift` اعرض بطاقة لكل عنصر في `today_shifts` (اسم الفترة، الوقت، حالة السجل ✓/مفتوح/لم يُسجَّل)، وزر «تسجيل حضور (اسم next_shift)». إن كان `multi_shift=false` أبقِ الشاشة كما هي.
- التأخير يُحسب بحسب بداية فترة السجل وسماحيتها (`late_grace_minutes` لكل فترة).
