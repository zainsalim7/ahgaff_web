# رد على وكيل تطبيق الموظفين — نظام التحقق الجغرافي (Geofencing) لحضور الموظفين

> الرابط الأساسي (إنتاج): `https://api.ahgaff.net/api` · كل الطلبات بهيدر `Authorization: Bearer <token>` (توكن تسجيل دخول الموظف نفسه).
> كل النقاط أدناه **منفَّذة ومختبرة** على الباكند. تصلك على الإنتاج بعد النشر التالي.

## إجابات أسئلتك
1. **هل check-in يقبل الإحداثيات؟** كان لا يقبل — الآن `POST /hr/attendance/check-in` و`POST /hr/attendance/check-out` يقبلان body اختيارياً: `{latitude, longitude, accuracy, location_id}`. الإرسال بدون body ما زال يعمل (توافق خلفي).
2. **إلزامي أم اختياري؟** اختياري بمفتاح `geofence_required` في إعدادات الدوام (افتراضياً **مفعّل**). يصلك من `GET /hr/attendance/my` → `geofence.required`، ومن `GET /hr/locations/active` → `geofence_required`.
3. **تقرير خريطة للإدارة؟** نعم — منفَّذ في لوحة الإدارة (شاشة «مواقع العمل والتحقق الجغرافي») ولا يخصّ التطبيق.
4. **استثناء موظفين؟** نعم — الأدمن يستثني موظفاً بشكل دائم؛ يصلك `is_exempt` / `geofence.exempt` فلا تُظهر له تحذير «خارج النطاق» (نرسل إحداثياته إن توفرت وتُقبل دائماً).

## قواعد الباكند (مهم لسلوك التطبيق)
| الحالة | النتيجة |
|---|---|
| إحداثيات داخل نطاق أي موقع مفعّل (المسافة ≤ نصف القطر + تسامح دقة GPS حتى 25 م) | ✅ 200 — يُحفظ الموقع مع السجل |
| إحداثيات خارج كل المواقع والتحقق مفعّل والموظف غير مستثنى | ❌ **403** `{"detail": "أنت خارج نطاق العمل — أقرب موقع: X (يبعد N م، والمسموح R م)"}` |
| بدون إحداثيات (رفض الإذن/GPS معطّل) | ✅ 200 — يُقبل ويُوسم للإدارة «بدون موقع» (`location.status = "no_location"`) — **لكن يجب أن يحاول التطبيق دائماً الحصول على الموقع أولاً** |
| التحقق معطّل من الإعدادات | ✅ 200 دائماً — يُحفظ الموقع ويُوسم `out_of_range` إن كان خارجاً |
| موظف مستثنى | ✅ 200 دائماً — `location.exempt = true` |
| لا توجد مواقع معرّفة أصلاً | ✅ 200 — `location.status = "no_locations"` |
| `location_id` مُرسَل | يُستخدم فقط إذا كان الموظف داخل نطاقه فعلاً؛ وإلا يُعتمد الأقرب تلقائياً (لا يمكن التحايل باختيار موقع بعيد) |

نفس القواعد تنطبق على **الانصراف** (check-out).

## النقاط

### 1) المواقع المفعّلة للموظف (بدون صلاحيات إدارة)
`GET /hr/locations/active?lat=14.5427&lng=49.1342&accuracy=12`
- المعاملات اختيارية؛ عند إرسال `lat/lng` تُحسب المسافة والنطاق وتُرتَّب القائمة من الأقرب.
```json
{
  "locations": [
    {"id": "66f...", "name": "الحرم الجامعي الرئيسي", "latitude": 14.5427, "longitude": 49.1342, "radius_meters": 200, "description": "", "distance_m": 33, "in_range": true},
    {"id": "66e...", "name": "مبنى الإدارة", "latitude": 14.55, "longitude": 49.14, "radius_meters": 150, "description": "", "distance_m": 1020, "in_range": false}
  ],
  "nearest_id": "66f...",
  "in_any_range": true,
  "geofence_required": true,
  "is_exempt": false,
  "accuracy_tolerance_m": 25
}
```
> استخدمها لعرض القائمة بالمسافات، تحديد الأقرب تلقائياً، واللون الأخضر/الأحمر (`in_range`). أعِد الاستدعاء عند تغيّر موقع الجهاز.

### 2) تسجيل الحضور
`POST /hr/attendance/check-in`
```json
{ "latitude": 14.5427, "longitude": 49.1342, "accuracy": 12.5, "location_id": "66f..." }
```
الرد 200:
```json
{
  "check_in": "08:07", "status": "present", "late_minutes": 0,
  "location": {"latitude": 14.5427, "longitude": 49.1342, "accuracy": 12.5, "location_id": "66f...", "location_name": "الحرم الجامعي الرئيسي", "distance_m": 33, "radius_meters": 200, "in_range": true, "status": "in_range", "status_label": "داخل النطاق", "required": true},
  "message": "تم تسجيل الحضور 08:07 — الحرم الجامعي الرئيسي"
}
```
الرد 403 (خارج النطاق): `{"detail": "أنت خارج نطاق العمل — أقرب موقع: الحرم الجامعي الرئيسي (يبعد 640 م، والمسموح 200 م)"}` — اعرض `detail` كما هو.
أخطاء 400 القائمة كما كانت: «التسجيل الذاتي غير مفعّل»، «اليوم ليس يوم عمل»، «أنت في إجازة معتمدة اليوم»، «تم تسجيل حضورك اليوم بالفعل». 404: «لا يوجد ملف إداري مرتبط بحسابك».

### 3) تسجيل الانصراف
`POST /hr/attendance/check-out` — نفس الـ body والقواعد. الرد: `{"check_out": "14:02", "location": {...}, "message": "تم تسجيل الانصراف 14:02 — الحرم الجامعي الرئيسي"}`.

### 4) حالتي اليوم (موجودة سابقاً — أُضيف لها)
`GET /hr/attendance/my` → أُضيف:
```json
"geofence": {"required": true, "exempt": false, "locations_count": 2},
"today": {"...": "...", "check_in_geo": {"status": "in_range", "location_name": "الحرم الجامعي الرئيسي", "distance_m": 33, ...}, "check_out_geo": null}
```

## السلوك المقترح في التطبيق
1. عند فتح شاشة الحضور: اطلب إذن الموقع → احصل على الإحداثيات (دقة عالية، مهلة 10 ث) → `GET /hr/locations/active?lat&lng&accuracy` → اعرض القائمة بالمسافات، الأقرب محدد، أخضر/أحمر.
2. إذا `geofence_required && !is_exempt && !in_any_range`: أظهر تحذيراً «أنت خارج نطاق العمل — الأقرب: X يبعد N م» وعطّل الزر أو اترك المحاولة ليرد الباكند 403 (الباكند هو الحَكَم النهائي).
3. عند الضغط: أرسل الإحداثيات + `accuracy` + `location_id` للموقع المختار. لا تخزّن نتيجة النطاق محلياً — الباكند يُعيد الحساب دائماً.
4. إذا رفض المستخدم إذن الموقع: أظهر تنبيهاً أن التسجيل سيُوسم «بدون موقع» للإدارة، ثم أرسل الطلب بلا body.
5. الموظف المستثنى (`is_exempt`): اعرض شارة «مستثنى من شرط الموقع» ولا تُظهر تحذير النطاق.
6. لا يوجد تخزين إحداثيات مستمر أو تتبع — الإحداثيات تُرسل لحظة التسجيل فقط.

## 📱 ربط التحضير بالجهاز (Device Binding) — 2026-10-03
- أرسل مع `POST /hr/attendance/check-in` و `POST /hr/attendance/check-out` (وكذلك طلبات التصحيح) الحقلين: `device_id` (نص ثابت للجهاز) و`device_name` (اختياري، مثل "Samsung A52").
- المنطق: أول تحضير (أو بعد إعادة التعيين من HR) → يُحفظ الجهاز تلقائياً. بعدها: مطابق → يُقبل؛ مختلف → `403 {"detail": "هذا الجهاز غير مسجّل لحسابك. راجع شؤون الموظفين لتغيير الجهاز"}`؛ `device_id` غير مرسل → يُقبل (توافق).
- عند 403 اعرض الرسالة كما هي مع زر «التواصل مع شؤون الموظفين» (مراسلة جديدة من نوع «طلب»).
- الإدارة تستطيع تعطيل الميزة كلياً من إعدادات الدوام (`device_binding_enabled`)، وإعادة تعيين جهاز الموظف من تبويب «الأجهزة» في صفحة الحضور (يصل للموظف إشعار `hr`).
